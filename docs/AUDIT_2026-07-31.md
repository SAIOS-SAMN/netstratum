## §4 FINDING — vacuous bugs (one known, two NEW in the drafted law)

**Known and law-bound (no action beyond U1):**
`verify_certificate` (`engine/solver-verify/src/certificate.rs`) is
vacuous as a work-verifier — it recomputes the hash chain from the
same prover-supplied (task, program, output) and returns `Intact`
for ANY fabricated triple; it detects tampering, never fabrication.
`U_DIRECTIVES.md` §2 already names this (THE REPLAY-COMPLETE LAW)
and boards the full replay as U1's `verify_work` (re-forge →
re-apply → re-chain). `mint_bound` is sealed at 0 until Ruling
Box 1, so nothing mints from a fake certificate today.

**NEW HOLE A — degenerate difficulty makes the replay vacuous.**
`Difficulty` rides the attacker-controlled work payload and
`verify_work` step 1 re-forges with it. `train_pairs: 0` re-forges
a task with an EMPTY training set — step 2's "maps EVERY training
pair" is then vacuously true, and an empty program whose output is
its own render passes all three steps at any claimed tier/word_len.
When Ruling Box 1 opens the rate, this mints for free. The drafted
witness list (U_DIRECTIVES §2, witnesses 1–6) does not cover it.

**NEW HOLE B — zero dimensions panic the judge.** `rows: 0` or
`cols: 0` drives `sample_grid` into
`Grid::new(...).expect("forged dimensions are consistent")`
(`engine/solver-verify/src/forge.rs`) — a panic inside the kernel's
call path. The kernel law is total-never-panics; a crafted payload
crashes the node (denial of service).

**One fix closes both:** refuse degenerate difficulty TYPED at
payload decode (the opaque-payload law already demands refuse-never-
guess for truncation/trailing/unknown — extend it to degenerate
fields), or better, carry the LADDER LEVEL on the wire instead of
the raw struct — `Difficulty::level`/`from_key` only produce sane
rungs. Land as witnesses 7 (train_pairs 0 refuses) and 8 (zero
dimension refuses, never panics) in U1's red-first list.

**Secondary (prover-side, non-constitutional today):**
- The volumetric path has NO verifier: `seal_volume` is private and
  `VolumeSolveRead::Solved.certificate` is a bare digest nobody can
  re-derive — decorative until the volumetric tier lands with one.
- A hand-built `VolumeTask` with an empty train is vacuously
  "Solved" by the empty program at depth 0 (`solve_volume`'s
  `closes` is `all()` over the empty set). The planar loader refuses
  "no training pairs"; the volume side has no guard.
- Doc drift inviting the vacuous reading: `engine/solver/src/lib.rs`
  ("`verify` replays it byte-exact") and `engine/kernel/CHARTER.md`
  ("`verify_certificate` checks it by replay", §5's guardrail
  discussion) — per the REPLAY-COMPLETE LAW the replaying function
  is `verify_work`; the certificate check alone is tamper-evidence.
  Tighten both sentences so no future seat wires the wrong function
  as the anchor.
